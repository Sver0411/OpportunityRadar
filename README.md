# OpportunityRadar

**不是把链接堆给你，而是把真正能行动的机会筛出来。**

从工作、科研到竞赛、开源和资助：找到更多可能，回到官方核实，判断是否适合，再决定先做什么。

> **真正稀缺的从来不是机会数量，而是知道哪些机会与你有关、现在仍然有效，并且值得占用你的时间。**

“帮我找几个机会”看起来只是一个搜索问题，现实中却至少包含五个不同的问题：

```text
我是不是漏掉了自己根本不会搜索的方向？
这个机会现在还开放吗？
我真的符合申请条件吗？
它值得我投入几天、几周，还是几个月吗？
如果我还不够格，现在做什么能让我离目标更近？
```

普通搜索往往把这些问题压缩成一页链接。OpportunityRadar 把它们重新拆开。

## 一份长清单，通常不是一个好答案

机会搜索最常见的失败，不是“什么都没找到”，而是找到得太轻易：

- 聚合站上的岗位看起来合适，打开官网才发现已经结束；
- 标题与你的方向一致，硬性条件却要求完全不同的学历或毕业时间；
- 同一个项目被十个网站转载，最后被当成十个不同机会；
- 推荐了二十件“值得做”的事，却完全不考虑你一周只有五小时；
- 告诉你“缺少经验”，却没有继续寻找能补上这段经验的真实入口。

OpportunityRadar 的目标不是把结果做长，而是让你一眼看懂：**哪些值得现在点开，为什么是它，以及下一步先做什么。**

## 它会多做哪几步

| 它做的事 | 解决的问题 |
| --- | --- |
| **扩大搜索范围** | 不只重复你给出的关键词，还会从 13 类机会和相邻方向中寻找你可能没想到的入口 |
| **回到官方核实** | 搜索结果只负责发现；开放状态、截止时间、要求和申请入口尽量以官方页面为准 |
| **判断资格** | 对照学历、毕业时间、语言、地点、身份与技能，明确区分符合、可能符合和无法判断 |
| **评估准备程度** | “能申请”不等于“已经准备好”，会列出材料、能力和现实阻碍 |
| **比较投入与价值** | 同时考虑时间、费用、准备难度、能留下的成果和未来可能打开的路 |
| **寻找桥接机会** | 从目标机会的真实要求中发现缺口，再继续寻找能补作品、研究、领导力或公开贡献的项目 |
| **安排机会组合** | 在你的时间预算里区分现在要做、低成本尝试、补缺口、长期准备和高上限选择 |
| **保留搜索记忆** | 可在本地记录看过、收藏、忽略和已经申请的机会，减少重复并发现重要变化 |

## 它怎样工作

一次完整的寻找，不是“搜一次，然后返回结果”。

```text
理解你的阶段、目标和限制
        ↓
展开类别、相邻方向、地区与搜索语言
        ↓
广泛发现候选，再找到正式来源
        ↓
核实开放状态、截止时间、资格与申请入口
        ↓
标准化日期、合并重复项、排除硬性冲突
        ↓
判断匹配、准备度、优先级与当前投入价值
        ↓
组成一份在现实时间预算内能够执行的机会组合
```

这里有四个故意分开的判断：

| 判断 | 它回答什么 |
| --- | --- |
| **匹配** | 这个机会与我的背景和目标是否相关？ |
| **资格** | 官方条件是否允许我参加或申请？ |
| **准备度** | 即使能申请，我离真正开始还差什么？ |
| **当前价值** | 综合时间、成本、成果和未来作用，它现在值得投入吗？ |

“很适合”“能申请”“准备好了”和“现在值得做”，从来不是同一件事。

## OpportunityHandbook × OpportunityRadar

OpportunityRadar 有一个天然的搭档：[**OpportunityHandbook**](https://github.com/Sver0411/OpportunityHandbook)。

| | [OpportunityHandbook](https://github.com/Sver0411/OpportunityHandbook) | [OpportunityRadar](https://github.com/Sver0411/OpportunityRadar) |
| --- | --- | --- |
| **它解决什么** | 看懂有哪些路、每条路的成本、门槛、退路和长期价值 | 找到当前真实存在的机会，并核实能否参与、何时行动 |
| **最适合的时刻** | “我不知道该往哪里走”或“两个方向应该怎样选” | “方向大致清楚了，现在有什么值得申请或参加” |
| **最终产物** | 一张更清楚的地图和一套判断方法 | 一组经过筛选的现实入口和下一步动作 |

最简单的搭配方式：

```text
先用 Handbook 看清路
        ↓
把“我想变好”说成一个具体目标
        ↓
用 Radar 找到当前仍开放的真实机会
        ↓
通过行动留下作品、经历、关系与新证据
        ↓
带着新的信息，再回到地图上做下一次选择
```

### 一个在职转型的例子

假设你做了五年产品经理，开始考虑人工智能方向。

先用 Handbook 分清：你想换的是行业、岗位还是工作内容；哪些既有能力可以带走；你愿不愿意接受短期降薪；什么样的作品或经历能够证明这次转型不是一句愿望。

然后把更清楚的目标交给 Radar：

```text
我做了五年产品经理，想转向人工智能产品。
暂时不裸辞，每周能投入 6 小时。
请帮我找目前仍开放、能留下真实作品或行业经历的项目、开源计划、竞赛和岗位，
并告诉我哪些适合现在做，哪些需要先补能力。
```

Handbook 帮你避免在错误的问题上努力，Radar 帮你避免在过期或不适合的机会上浪费时间。

## 它适合谁

| 你现在的情况 | Radar 可以寻找什么 |
| --- | --- |
| **学生或应届生** | 实习、科研、比赛、交换、奖学金、开源与作品项目 |
| **正在工作** | 新岗位、行业项目、进修、专业社群、演讲与公开贡献 |
| **准备晋升** | 能积累领导力、管理经验、行业影响力或公开成果的机会 |
| **准备转岗或转行** | 目标岗位，以及能够补经验、技能和作品的过渡项目 |
| **准备出国发展** | 海外工作、升学、研究、资助、交流与跨国项目 |
| **管理者或资深从业者** | 行业组织、导师计划、评审、演讲、合作研究与创业项目 |
| **重返职场或自由职业** | 远程、灵活、短期项目，以及能够重新建立履历的机会 |
| **方向还不明确** | 投入较小、差异明显的尝试，用真实体验帮助判断方向 |

它不限制专业。设计、商科、工程、生物、环境、人文、医疗和技术方向都可以使用。

## 它会寻找哪些机会

Radar 使用 13 类机会作为搜索空间，而不是把所有问题都变成求职：

| 类别 | 常见内容 |
| --- | --- |
| **职业机会** | 实习、校招、社招、兼职、自由职业与企业培养计划 |
| **科研机会** | 研究助理、本科科研、实验室项目、暑研与研究实习 |
| **竞赛** | 学科、算法、设计、商业、硬件、创新创业与行业挑战 |
| **升学与教育** | 研究生项目、交换、夏校、访问学生与短期课程 |
| **语言** | 考试、奖学金、交流、比赛与语言项目 |
| **技能与资源** | 认证、训练、学生开发包、云资源与硬件计划 |
| **开源** | 导师计划、贡献入口、赏金、社区项目与维护者招募 |
| **兴趣** | 创客、摄影、音乐、游戏、无人机等兴趣型机会 |
| **资助** | 奖学金、研究资助、差旅资助、资源与费用减免 |
| **活动** | 大会、工作坊、开放日、宣讲和行业聚会 |
| **项目** | 企业课题、共创项目、数据集项目与真实协作 |
| **创业** | 加速器、孵化器、创业比赛与团队招募 |
| **人脉与社区** | 导师、校友、学生分会、专业协会与行业组织 |

类别是发现入口，不是推荐配额。没有足够好的结果时，它会少推荐，而不是用弱机会把栏目填满。

## 你会得到什么结果

结果首先按行动状态分开：

| 结果区域 | 代表什么 |
| --- | --- |
| **现在值得看** | 官方来源和近期开放信息已经核实，没有发现明确资格冲突 |
| **值得继续确认** | 方向有价值，但状态、来源或资格仍有关键未知信息 |
| **已经结束或不符合** | 已过期、已关闭，或存在明确的硬性条件冲突，并说明原因 |

一条重要推荐不会只有名称和网址，而会尽量回答：

```text
这是什么机会，主办方是谁？
为什么它与你有关？
哪些申请条件已经确认，哪些还不知道？
现在是否开放，截止时间来自哪里？
要投入多少时间、费用和准备成本？
完成以后能留下什么？
接下来应该先打开哪个页面、确认哪件事？
```

如果你给出每周可用时间，它还会检查整组推荐是否超过预算。你得到的不是一个脱离现实的排行榜，而是一份能够真正开始执行的组合。

## 可以这样问

```text
我是视觉设计专业的学生，最近有什么能留下真实作品的项目？

我工作五年了，想升管理岗，有哪些机会能补领导力和行业影响力？

我在做嵌入式开发，想转到边缘人工智能，现在可以参加什么？

我准备去德国工作或读研，有哪些项目、资助和交流机会值得看？

我离开职场两年了，想重新开始，有没有时间灵活的项目？

我暂时不想换工作，每周只有 5 小时，有什么能为晋升铺路？

我还不知道以后想做什么，帮我找几个差别大一点的方向。
```

不需要先填写一张完整表格。一句话就能开始；只有缺少的信息真的会改变结论时，才需要继续补充。

## 安装与使用

把仓库放进支持 Agent Skills 的工具的 Skills 目录。最终目录名应为 `opportunity-radar`。

以 Codex 为例：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/Sver0411/OpportunityRadar.git \
  ~/.codex/skills/opportunity-radar
```

安装完成后，直接用自然语言提问即可。

发现和核实真实机会需要宿主能够联网搜索并打开网页。辅助脚本支持 Python 3.8+，只使用标准库，不需要额外 API Key；没有 Python 时仍然可以按 [`SKILL.md`](SKILL.md) 中的流程工作，但日期、去重和评分会改为人工判断。

## 它坚持什么

- **重要信息尽量回到官方页面。** 第三方来源可以帮助发现，不能代替正式确认。
- **不知道就是不知道。** 用户没有说过、页面没有写清的内容，不会被猜成事实。
- **硬性冲突优先。** 明确要求博士生的项目，不会因为方向很匹配而推荐给本科生。
- **开放状态必须有证据。** 页面没有截止时间，不等于项目仍然开放。
- **准备度不是录取概率。** 它可以告诉你还差什么，不会编造“你有多少概率成功”。
- **宁可少，也不凑数。** 没有达到来源和质量门槛的条目，不会为了好看进入主推荐。
- **行动权留给用户。** 不会代替你报名、发信、注册账号或上传个人资料。

## 使用边界

机会信息会变化。即使一次核实过，真正行动前也应重新打开官方网站确认最新要求。

OpportunityRadar 不能保证搜遍所有机构，也不能保证申请结果。它能做的是扩大你能看见的范围、提高信息可信度，并减少把时间浪费在过期、不适合或价值很低的机会上的可能。

可选的用户资料和查看记录保存在本地 `.opportunity-radar/`，辅助脚本不会主动上传这些文件。
