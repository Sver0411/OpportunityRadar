# 真人测试（Real User Testing）—— 第一阶段

**目的**：发现"系统哪里让真实用户觉得没用、奇怪、太多、太泛、或者漏掉重点"。
不是证明系统成功，也不是追求统计显著性。

## 第一阶段：5 类用户 × 1–2 人

| 类别 | 画像要点 | 建议招募 |
|---|---|---|
| A 大学生 | 在读本科，方向未定或已定 | 1–2 人 |
| B 研究生 / 准备升学 | 在读硕士或准备申请 | 1–2 人 |
| C Early-career | 工作 1–3 年 | 1–2 人 |
| D Mid-career / 转行 | 工作 5 年以上，或在转行 | 1–2 人 |
| E 没有明确目标的人 | 明确说"不知道想做什么" | 1–2 人 |

**不要伪造成绩。** 没做的 session 就留空，记录里写明未执行。

## 流程（每个 session 约 30–40 分钟）

1. 读 `CONSENT_OR_PRIVACY_NOTE.md`，取得口头同意
2. 让用户用**自己的话**描述现状（不引导、不提示用词）
3. 系统按正常流程跑一次（Profile → Discovery → Verification → Gap → Bridge → Portfolio → 回答）
4. 把回答原样给用户看，**不要解释、不要辩护**
5. 记录用户行为：点了什么 / 收藏了什么 / 说会去做什么
6. 问 `SESSION_TEMPLATE.md` 里的 6 个主观问题
7. 存到 `usertests/real/sessions/<日期>-<代号>.md`（代号，不写真实姓名）

## 记录纪律

- 只记录**观察到的事实**（用户说了什么、点了什么），不写"用户应该会喜欢"
- 负面反馈必须原样保留，不允许润色成中性表述
- 用户明确不喜欢的条目，照实记，不要替系统解释
