# User Tests — v0.2-beta 真人测试彩排

4 个**虚构**测试用户（标记 `SIMULATED USER SESSION`），用白话输入跑完整 Skill 流程，
产出用户实际会看到的白话回复。目的：在找真人测试之前，先用仿真会话检验端到端体验。

| 用户 | 白话输入 | locale 计划 | 搜索 | Recommended | Worth verifying | 彩排发现 |
|---|---|---|---|---:|---:|---|
| u1 会计转数据（杭州大二） | "学会计…在自学 Excel 和一点 Python…不太想去太远的地方" | china / zh-CN | 5 搜 4 抓 | 3 | 3 | **城市级定位缺失**（杭州/江浙沪无法表达，退到国家层） |
| u2 计算机大三焦虑秋招 | "现在这时间点还有什么能投的？秋招是不是没戏了" | china / zh-CN | 5 搜 4 抓 | 3 | 2 | 秋招时间线可从官方源核实；**届别歧义用追问解决**（2027/2028 届） |
| u3 专科游戏美术 | "有没有比赛或项目能让作品集好看点的？远程的最好" | china / zh-CN | 5 搜 4 抓 | 3 | 2 | **专科偏见未触发**：对口赛道全部"学历不限"；两条最对口赛道当天截止被标紧迫 |

每份 `transcript.md` = 用户原话 → 实际做的事（locale/queries 简列）→ **给用户的最终回复**（三区结构）。
机器记录在 `record.json`（画像、locale 计划、queries、结果、追问、findings）。

## 彩排确认有效的部分

- **白话输入 → 结构化画像**：4 条口语输入都正确抽出专业/年级/地区/语言/意图，缺失项留空而非假设。
- **三区输出自然**：Recommended now / Worth verifying / Closed 的分离在白话回复里读起来不生硬。
- **gates 透明落地**：过期项被排除且一句话带过；无官方来源的聚合站结果全部降入"值得继续核实"。
- **追问质量**：每场 1–2 个追问都直接决定推荐方向（届别、学校层次、自费意愿、方向偏好）。

## 彩排暴露的真实问题（进 backlog）

1. **城市级定位缺失**（u1）：`locales.py` 只到国家级，"杭州/江浙沪"意图无法表达 → 需要一个
   city/region 级的偏好字段与查询策略（暂由 Agent 在 query 里手动带地名弥补）。
2. **紧迫性展示**（u3）：两条最对口赛道当天截止，只靠一句"今天截止"提示——对真实用户应更醒目。
3. **N3 类语言诚实但需要给路径**（u4）：如实说不够之后，必须马上给出可行替代（英语项目），
   这一点本轮做到了，但值得在 locale 文件里固化成规则。

## 与真人测试的差距

这些是**仿真会话**：用户是虚构的，搜索预算受限（≤5 搜 + ≤4 抓），且没有真实用户的主观反馈
（"这个机会我真的会去申请吗"）。真人测试（3–10 人）仍需验证：用户是否真的行动、是否觉得推荐准、
追问是否被耐心回答、结果数量是否合适。
