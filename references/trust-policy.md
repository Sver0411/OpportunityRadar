# Source Trust Policy

决定"哪条信息可以当事实用"。OpportunityRadar 的输出可信度完全取决于这一层。

**一句话规则：Tier C/D 用来发现，Tier A/B 用来确认。**

---

## 1. 来源分级

### Tier A — 权威一手来源

事实效力最高，可作为 `official_url` 与事实依据。

- 项目/赛事/计划的**官方网站**
- 企业官网（校招页、careers、学生计划专页、投资者关系之外的公告页）
- 大学官网（院系页、招生页、国际处、实验室官方页）
- 政府/公共机构官网
- 实验室/研究中心官网
- 学术会议官网、基金会官网

### Tier B — 机构次级来源

可用于确认，但当与 Tier A 冲突时以 A 为准。

- 学校就业中心 / 教务 / 研究生院发布页
- 学术组织与行业协会（学会、IEEE/ACM 学生分会等）
- 官方合作机构（官方指定的报名平台、承办方页面）
- 企业官方社交媒体账号的公告（仍优先回官网页面）

### Tier C — 聚合平台与社区

只用于**发现**。不得作为关键事实的唯一来源。

- LinkedIn、招聘平台（Boss/实习僧/マイナビ/リクナビ 等）
- 比赛聚合站、活动聚合站、奖学金聚合站
- 技术社区（知乎/Reddit/CSDN/Stack Overflow/Zenn/Qiita）的讨论帖
- 学校社团/自媒体的汇总名单

### Tier D — 非官方二手内容

只用于发现 + 线索提示。**任何关键事实都不得仅有 D 来源。**

- 博客、论坛、个人帖子
- 转载、二手整理清单
- 非官方公众号文章、内容农场
- AI 生成的汇总页

## 2. 两个 URL 必须分开记录

| 字段 | 含义 | 要求 |
|---|---|---|
| `discovery_url` | **最早发现**该机会的页面（可能是 C/D） | 必填，标明来源 tier |
| `official_url` | 用来确认事实的**官方页面** | 找到就给；找不到写 `null` 并说明 |

禁止把 C/D 的链接塞进 `official_url`。禁止凭"应该是这个网址"拼一个官方链接。

**Deep link 政策**：只记录**实际打开并在其中读到该事实**的 URL。
不要为了好看把 URL 修剪成"看起来更官方"的首页（除非你确认该事实就在被记录的页面上）。

---

## 3. Why 验证：必须确认的 3 件事（Step 7）

对每条准备推荐的机会，在官方页面确认这 3 项：

1. **时间**：报名开放/截止、活动日期（或明确"滚动招募/常年"）
2. **资格**：学历、年级、专业、国籍/签证、语言
3. **入口**：官方报名路径确实存在（表格/邮箱/系统链接）

确认完写 `last_verified`（YYYY-MM-DD）+ `verification_status`。

### verification_status 取值

| 值 | 含义 |
|---|---|
| `verified_official` | 3 项关键事实全部在 Tier A/B 页面确认 |
| `partially_verified` | 官方页面存在，但部分事实（如语言要求）页面未写 |
| `unverified` | 只在 C/D 找到，未获取官方确认 |
| `conflicting` | 官方与第三方不一致，已在记录中写明差异 |
| `expired` | 官方页面显示窗口已结束 / 项目已停办 |

---

## 4. 冲突处理（必须显式记录）

当第三方与官方不一致时：**以官方为准**，并在输出里写出差异。

```
第三方（实习僧）：Deadline 9月20日
官方（企业校招页）：Deadline 9月25日
→ 采用 9月25日，verification_status = conflicting
→ 输出注明："第三方信息与官方存在差异，已采用官方日期。"
```

规则：
1. 以**更新时间更晚**的官方页面为准（页面自身有更新日期时优先参考）。
2. 官方页面内部自相矛盾（如中英版日期不同）→ 采用更**保守**的（更早的截止日），
   并注明冲突。
3. 冲突无法解决时，两个日期都写出，不要偷偷选一个。

---

## 5. 新鲜度（staleness）

信息会过期。判断标准：

| 机会类型 | `last_verified` 超过多久需重新确认 |
|---|---|
| 竞赛 / 一次性项目 | 14 天 |
| 实习 / 校招岗位 | 30 天 |
| 奖学金 / 长期项目 | 60 天 |
| 常年开放的资源类（credit、认证、社区） | 180 天 |

超过阈值的记录：要么重新打开官方页确认后再推荐（更新 `last_verified`），
要么在输出里标注"信息可能已过期，建议以官网为准"。

## 6. 特殊场景

- **登录墙**：官方页面需要登录才能看内容 → 标注
  `access: login-gated`，不要编造墙后内容；可用公开的补充说明（如 FAQ 页）辅助。
- **JS 渲染页面**：优先用宿主 Agent 的浏览器能力；抓不到正文时标注"页面正文未获取"，
  不要用标题之外的推测填空。
- **PDF 简章**：属于 Tier A 内容，但记录 URL 时给 PDF 直链，
  并在 `summary` 里写明"以 PDF 简章为准"。
- **中国场景**：公众号文章多为 D 级；若来自官方机构账号，仍优先找其官网/教务页。
- **日本场景**：企業採用ページ 为 A；マイナビ/リクナビ 为 C（可用于发现与校招时间线）；
  大学 研究室ページ 为 A；教授个人 ブログ 为 D。
- **聚合名单**（"50 个适合学生的比赛"这类清单）：整份清单都是 D。
  从中发现线索后，逐条回官方页确认，确认不到的不要推荐。

---

## 7. 禁止行为

- ❌ 编造官方 URL，或把猜测的 URL 当成"官方来源"。
- ❌ 找不到官方页时静默省略，让读者以为是官方信息 → 必须写"未找到官方确认来源"。
- ❌ 用二手来源支撑硬性资格（deadline、语言要求、学历要求）。
- ❌ 引用"某平台显示"而不给实际链接。
- ❌ 把过期页面当成当前机会（除非明确标为"往期参考/预计时间线"）。
