# Profile Building — 渐进式画像

Step 1 的执行规范。核心原则：

> **已有信息先用于搜索。只在某个缺失字段会显著改变结果时，才问一次。**

绝不因为缺字段而停止任务。绝不第一次接触就抛十几个问题。

---

## 1. 最小可用画像

出现下列**任意两个**信号，就足以开始一次 Discovery：

| 信号 | 例子 |
|---|---|
| 阶段 | 大二 / 研一 / 应届 / 2027 毕业 |
| 专业或领域 | 物联网 / 机械 / 日语 / 数学 |
| 技能或做过的事 | ESP32、C、做过一个小项目 |
| 兴趣方向 | AI Agent、无人机、摄影 |
| 目标 | 找实习 / 想读研 / 想充实一下 |
| 地区 | 想在日本 / 只考虑国内 / remote 也行 |

只有一句"最近有什么机会"没有任何画像信息时 → 问**一个**问题，且给出默认值让用户可以不答：

> "为了筛得准一点：你现在是什么阶段（年级/是否已毕业）、想找哪个方向？
> 也可以直接说'随便看看'，我就按通用方向来。"

---

## 2. 主动复用（不要重复问）

按顺序查找已有画像，找到就**不要**再问：

1. **宿主 Agent 的 Memory / 长期上下文**（专业、学校、年级、技能、兴趣、目标）
2. **本 Skill 的本地 profile**：`.opportunity-radar/profile.json`
3. **本次对话此前说过的话**（包括用户为了别的事提到的专业、项目、语言成绩）
4. **工作区里可读到的信息**（如项目 README、简历文件——仅当用户已授权且明显相关）

复用时要**说一句**，让用户能纠正：

> "按你之前提到的情况（物联网大三、C/Python/ESP32、关注 Embedded + AI Agent），我按这个来找。"

当前消息比历史画像优先。用户从“山东找工作”转问“日本留学”时，本轮把目标和
地点改为日本教育机会；不要删除或悄悄改写长期画像。Full Mode 把本轮
`goals` / `constraints` 写成临时 context JSON，同时交给 `locales.py` 搜索规划和
`score.py --context` 评分。仅当前消息没提到的偏好才继承历史画像。

---

## 3. 什么时候该问（判定规则）

只在这些字段缺失、**且**它会实质改变搜索结果或资格判断时问一次：

| 字段 | 缺失的影响 | 值得问吗 |
|---|---|---|
| 年级 / 毕业年份 | 决定 eligibility 生死线（校招、夏令营、インターン） | **高** — 最常值得问 |
| 目标（求职/科研/竞赛/纯兴趣） | 决定搜哪几类（Mode 选择） | **高** |
| 地区 / 是否能远程 | 决定语言与地点过滤 | 中 |
| 专业 / 领域 | 决定搜索矩阵 | 中（用户通常已说） |
| 技能栈 | 影响 skill_fit 与 query 精确度 | 低（可从结果反推） |
| GPA / 语言成绩 | 影响少数硬性门槛 | 低（除非机会明确要求） |
| 留学预算 / 授课语言 / 毕业后去向 | 会改变国家、学校与项目排序 | 留学推荐时高；未提供则先给有条件的建议并问 1–2 个关键问题 |
| 每周可投入时间 | 影响 time_commitment 过滤 | 低 |

**提问纪律**：
- 一轮最多 **1–2 个**问题。
- 先给结果、再补问（"先按现有信息给你找了一轮，如果你能补上毕业年份，我能筛掉一批申不了的"）。
- 绝不因为等问题答案而空转一轮。

---

## 4. 禁止猜（never guess）

- 用户没说年级，不要按"大三"推断。`current_year: null`。
- 用户没说学校，不要按"985/普通院校"推断。
- 用户没说语言能力，不要因为目标地区是日本就填 JLPT。
- 缺失 → `null`。`null` 会影响判断时，写"这里缺信息，会影响筛选"。

---

## 5. 本地 profile（可选层）

仅当宿主 Agent 不支持 Memory，或用户明确要求保存时使用：

```
.opportunity-radar/profile.json
```

结构见 `schemas/profile.schema.json`。写入纪律：

- 只写用户**明确说过**的内容；
- 每条可加 `_source: "user_stated" | "user_confirmed" | "inferred_pending"`；
- `inferred_pending` 的条目**不得**用于资格判断，只能用于搜索扩词；
- 用户说"我不再做 X 了"→ 更新，不要留旧值；
- 不要把简历、联系方式、身份证号、学号等敏感信息写进去。

示例（用户在对话里说了这些话）：

```json
{
  "education": { "degree": "undergraduate", "major": "IoT Engineering", "current_year": 3, "school_country": null },
  "skills": [{ "name": "Python", "level": "unknown" }, { "name": "C", "level": "unknown" }, { "name": "ESP32", "level": "intermediate" }],
  "interests": ["AI Agent", "Embedded", "Robotics", "Drone"],
  "goals": [{ "type": "internship", "priority": "high" }, { "type": "research", "priority": "medium" }],
  "constraints": { "preferred_country": ["Japan", "China"], "remote": true },
  "_source": "user_stated"
}
```

注意上例：用户没说的字段一律 `null`，不填默认值。

---

## 6. 画像更新

- 更新前先确认：只有用户明确表述或确认过的信息才写入。
- 观察到偏好但用户没说过时 → **建议**而非修改：
  > "你连着看了几条 Embedded / TinyML 相关的机会，要不要我把这个方向权重调高，下一轮多往这边找？"
- 不因一次 `ignored` 就永久删掉某个方向。

---

## 7. 反模式

- ❌ 一上来问 10 个字段的问卷。
- ❌ 缺字段就回"请先补充信息"，然后什么都不搜。
- ❌ 把缺失字段填成"一般情况"。
- ❌ 用户已说过的话又问一遍。
- ❌ 把画像写成大段叙述而不是结构化字段（后续脚本要用）。
